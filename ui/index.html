DocPilotdocument Q&A with retrieval and security checks
Checking server...

Searches the loaded corpus, extracts an answer span, and shows where it came from. Press Enter to ask, Shift+Enter for a new line.

These checks are pattern-based (regular expressions). They catch common phrasings of prompt injection and common PII formats. Reworded attacks and many PII formats (names, addresses, international phone numbers) are not detected.

Injection check

Runs the same patterns the API applies to questions (query check) or uploaded documents (document check).

PII redaction

The same redaction runs on both ingestion paths (API upload and ingest.py) and on audit log previews.

Audit log

Needs an admin key when the server runs with REQUIRE_AUTH=1. Question previews are stored with PII redacted. A row is flagged when the question had PII, was blocked, or the answer's grounding was below 0.5.

Open this tab or press Refresh to load the log.

API key

Only needed when the server runs with REQUIRE_AUTH=1. Sent as the X-API-Key header. Stored in this browser only, and only if you tick the box.

How a question is answered

  1. Screen. The question is checked against injection patterns. A match returns an error and is logged.
  2. Retrieve. BM25 always. When the embedding model loads, dense retrieval (BGE + ChromaDB) is fused with BM25 by reciprocal rank fusion, and a cross-encoder reranks the top candidates. The mode in the header shows which of these is active.
  3. Extract. An extractive QA model (RoBERTa, ONNX, INT8) picks an answer span from the retrieved passages.
  4. Synthesize (optional). With a Groq API key, an LLM writes the answer from the top passages. Without one, the extracted span is returned.
  5. Score and log. Grounding is the share of answer words found in the passages. It is a visibility signal, not a correctness check. Each query is written to the audit log.

What is measured, and what is not

  • INT8 quantization made the ONNX model about 4x smaller (496 MB to 125 MB) and one 384-token CPU forward pass about 2 to 3x faster. A full request runs several passes plus retrieval, so it takes longer.
  • F1 and exact-match scores are not shown here. The current eval set is templated and a simple keyword baseline beats the model on it, so those numbers do not show answer quality.
  • GPU latency has not been measured.
